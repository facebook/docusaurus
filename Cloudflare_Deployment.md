Cloudflare Deployment Documentation: Open-Source Website (Docusaurus)
Technical Architecture & Deployment Guide for Cloudflare Workers Static Assets & Pages
1. Overview & Architecture
Objective: Deploy an open-source static documentation website to Cloudflare's global edge network with automated CI/CD from GitHub.
Source Repository: https://github.com/DevangKore17/docusaurus (forked from facebook/docusaurus).
Hosting Architecture: Cloudflare Workers Static Assets / Cloudflare Pages. Static and JAMstack sites do not require manual Docker containerization; Cloudflare compiles the source code in its managed build container and distributes the compiled static assets across its global CDN with automatic SSL/TLS and unlimited bandwidth.
2. Prerequisites
A GitHub account with a forked or initialized open-source repository.
A free Cloudflare account with access to Workers & Pages.
Understanding of the repository's build structure (monorepo vs. standalone project) and runtime requirements.
3. Step-by-Step Deployment Guide (Cloudflare Workers Builds)
Step 1: Connect GitHub Repository
Log in to the Cloudflare Dashboard.
Select "Create app" under "Ship something new" (or navigate to Build > Compute > Workers & Pages).
Authorize GitHub and select the target repository (DevangKore17/docusaurus).
Step 2: Configure Build & Deploy Commands
Because DevangKore17/docusaurus is a monorepo without a root wrangler.jsonc file—and includes a Netlify-specific _redirects file incompatible with Cloudflare Workers Static Assets—configure the following commands in the setup screen:

Project name: docusaurus
Build command: pnpm build:website:en && rm -f ./website/build/_redirects
(Builds only the English documentation site after postinstall compiles internal workspace packages, and removes the incompatible Netlify _redirects file from the compiled build output before upload.)
Deploy command: npx wrangler deploy --assets=./website/build --compatibility-date=2026-04-01
(Passes the compiled output directory and compatibility date inline to Wrangler to deploy directly onto Workers Static Assets without requiring a configuration file in the repository.)
Preview command: npx wrangler versions upload --assets=./website/build --compatibility-date=2026-04-01
(Alternatively, disable "Enable Preview builds" if preview URLs are not required.)
Step 3: Configure Advanced Settings & Environment Variables
Root Path: /
API Token: Leave as + Create new token (auto-generated by Cloudflare).
Environment Variable 1: NODE_VERSION = 26 (satisfies the repository's Node >=26.13 engine requirement).
Environment Variable 2: NODE_OPTIONS = --max-old-space-size=4096 (prevents V8 out-of-memory errors during monorepo bundling).
Step 4: Deploy & Verify
Click "Save and Deploy".
Cloudflare clones the repository, installs dependencies via pnpm, builds the static assets into website/build, strips the incompatible _redirects file, and publishes the site to a live *.workers.dev URL.
Any subsequent git push to the main branch automatically triggers a new CI/CD build and deployment.
4. Troubleshooting Notes
Node.js Engine Version Mismatch (ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL): The upstream Docusaurus main branch enforces Node.js >=26.13. Setting NODE_VERSION = 26 resolves this during build execution.
Invalid _redirects Configuration (Cloudflare API Error 100324): The upstream repository contains website/static/_redirects formatted for Netlify (containing 404 status codes, splats, and absolute URLs), which Cloudflare Workers Static Assets rejects. Removing ./website/build/_redirects post-build (or deleting website/static/_redirects in Git) resolves the upload failure.
